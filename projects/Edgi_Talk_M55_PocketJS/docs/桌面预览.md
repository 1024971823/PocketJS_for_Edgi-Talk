# 桌面预览

`tools/preview/build.sh` 把固件里的 PocketJS C 代码、QuickJS，以及 Rust 界面核心和 RGB565 渲染器，编成一个 x86 程序，用脚本点击跑当前的 `.pocket`，再把画面存成 PNG。用来看界面，不用来当板子上的帧率。板子的软件光栅大约比这台电脑慢 50 到 60 倍。

## 要先准备的东西

- gcc、bun、python3 和 Pillow
- 主机版 Rust 静态库，放在 `$PREVIEW_OUT/cargo/` 下（默认 `/tmp/pjs-preview`）：
  - `cargo/ui-core/release/libpocketjs_idf_ui_core.a`
  - `cargo/render-rgb565/release/libpocketjs_idf_render_rgb565.a`

这两个库是 x86 的，和烧到板子上的 `thumbv8m` 库不是同一份。脚本找不到它们会直接退出，并指向本文件。

界面包要已经打好，见 [编译与烧录](编译与烧录.md)。预览读的是固件工程里嵌进去的那份包。

## 跑

在固件工程根目录：

```sh
tools/preview/build.sh [perfect|idle] [歌曲序号] [帧数]
```

| 参数 | 默认 | 含义 |
| --- | --- | --- |
| 模式 | `perfect` | `perfect` 按谱面点击；`idle` 进舞台后不点 |
| 歌曲序号 | `2` | 内置曲 0、1、2 |
| 帧数 | `2000` | 跑多少个 30 Hz 帧 |

输出在 `/tmp/pjs-preview`（用 `PREVIEW_OUT` 换目录）：

- `shots/*.png`：截图
- 终端里的损伤统计：每帧几个区域、多少行、有没有整屏重绘

整屏重绘意味着绘制列表的结构变了（节点出现或消失、空文本、缩放种类变了）。板上这种帧要零点几秒。看这个数字，不看桌面上的毫秒数。

`tools/preview/synth_test.c` 是在电脑上单独跑音频合成的小程序，不经过界面。
