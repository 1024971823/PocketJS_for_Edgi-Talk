# 性能测量

`tools/bench/` 里的脚本通过 KitProg3 读 M55 的内存，不需要串口。点击类的测量要求固件是用 `POCKETJS_DEBUG_TOUCH=1` 编的，见 [编译与烧录](编译与烧录.md)。正式烧录不要留着这个开关。

依赖：Python 3、Pillow（出 PNG 时）、`b/work/tools/openocd`。脚本用 `arm-none-eabi-nm` 从 `rt-thread.elf` 里查符号地址，所以测的必须是刚刚编出来的那一版。

在 `tools/bench/` 下运行。默认会先复位板子再等大约 40 秒开机。`--no-reset` 跳过这一步，用在板子已经停在主页上的时候。

## 帧耗时

```sh
python3 stage_bench.py                  # 进第一首歌的舞台，量 3 秒
python3 stage_bench.py --song 2         # 第 3 张卡
python3 stage_bench.py --home-only      # 只量主页
python3 stage_bench.py --transition     # 主页到选歌，再回到主页
python3 stage_bench.py --window 6 --settle 4
```

打印每个呈现帧的 UI、准备、渲染、送显毫秒，以及区域数。后面的 LCD 几行是驱动里的分段计时（清缓存、旋转、提交、等待），单位是每次送显。CPU 时钟默认按 400 MHz 换算，不对就设 `CORE_HZ`。

`--transition` 的数字是整段切换的合计，不是每帧平均。`render` 大、`regions` 只有几个，说明发生了整屏重绘。

## 截屏

坐标是界面上的 400×240，不是面板的 800×480。

```sh
python3 shot.py "wait:40000" "shot:/tmp/home.png"
python3 shot.py --no-reset "tap:330,20" "wait:2500" "shot:/tmp/calendar.png"
```

`wait` 的单位是毫秒，`tap:x,y` 点一下。脚本把扫描缓冲区转成横屏 PNG。正式固件没有触控注入，`tap` 不会生效，`shot` 仍然可以拍当前画面。

对照局部送显和整帧 GPU 旋转是否画得一样：

```sh
python3 scanout_check.py --no-reset          # 主页
python3 scanout_check.py --stage             # 先点进舞台
```

它先按局部路径抓一帧，再把 `g_lcd_force_full` 写成 1，等一帧整屏路径，然后数不同的像素。画面静止时这个数应该接近 0。正在动的舞台会差很多，因为两帧之间音符已经走了，不能据此判断画错。

## 函数热点

不暂停 CPU，反复读 PC 采样寄存器，再用 `addr2line` 归到函数。

```sh
python3 pc_profile.py --script transition --samples 1500
python3 pc_profile.py --script stage --top 20
python3 pc_profile.py --script none          # 停在当前页面
```

`--script transition` 会点主页的 PLAY 再开始采样，用来看切页时 CPU 在哪。样本占比是这段时间里的比例，包含空闲线程。

## 最近一次在板上量到的数

舞台大约 22.7 fps（UI 约 14 ms，软件渲染约 22 ms，送显约 1 ms）。主页空闲大约 24 到 30 fps，隐藏的页面越多，主页每帧的 UI 越贵。主页切到选歌大约 0.6 秒。第一次打开还没创建过的页面大约 2 秒，时间花在 JS 创建界面，不在送显。
