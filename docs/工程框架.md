# 工程框架

这个仓库是 Edgi-Talk BSP 的 **overlay/source-only** 仓库，不携带完整 RT-Thread BSP、工具链或 PocketJS/QuickJS 外部源码。工程框架把“源码可检查”和“完整可构建”分成两种明确模式，避免在只有源码的 checkout 中产生误导性的失败。

## 1. 目录边界

| 区域 | 责任 | 不应放什么 |
| --- | --- | --- |
| `projects/Edgi_Talk_M55_PocketJS/applications/pocketjs/` | M55 固件、PocketJS host glue、游戏/音频/网络实现 | 界面 TypeScript、电脑端 UI |
| `pocketjs-app/edgitalk-m55-smoke/` | 板上界面和游戏 TypeScript，打包为 `.pocket` | RT-Thread 驱动、外部 BSP 补丁 |
| `projects/Edgi_Talk_M55_PocketJS/tools/` | 构建、烧录、测试、预览、性能测量、契约检查 | 业务页面实现 |
| `projects/Edgi_Talk_M55_PocketJS/tools/edgitalk-companion/` | 电脑上位机、HTTP/蓝牙协议客户端和 mock 板 | 板端 C 实现 |
| `contracts/` | 跨 Python/C 的协议限制基线 | 机器生成的构建产物 |
| `bsp-patches/` | 需要打到上游 BSP 的最小补丁 | 本仓库私有的业务逻辑 |
| `libraries/` | 蓝牙控制器补丁和相关声明 | 通用应用代码 |

外部输入由 `tools/dependencies.lock` 管理：PocketJS、QuickJS-ng 的 commit，以及实际嵌入/链接的 `.pocket` 和 Rust 静态库哈希。

## 2. 运行时数据流

```text
PocketJS TypeScript UI
        │  QuickJS/native bindings
        ▼
applications/pocketjs (C: game, synth, dashboard, Wi-Fi, Bluetooth)
        │  JSON / chart / stats / score
        ├──────────────► Wi-Fi HTTP ──────► edgitalk-companion
        └──────────────► BLE GATT ────────► edgitalk-companion
```

- 界面只依赖 `native.ts` 暴露的能力，不在 TypeScript 中直接操作 RT-Thread。
- C 层负责输入校验、资源上限、音频时钟和存储；不能信任上位机发送的数据。
- 上位机 `edgitalk.py` 是协议客户端和离线谱面校验器，`mock` 提供无硬件测试服务。
- `contracts/chart-contract.json` 是人工可读基线；`check_contracts.py` 会核对 Python 常量和 C 宏，防止两端悄悄分叉。

## 3. 两种检查模式

| 命令 | 适用场景 | 行为 |
| --- | --- | --- |
| `make source-check` | GitHub Actions、只有本仓库源码 | 校验锁文件元数据、契约、路径、Python 测试和 host synth；跳过 SCons |
| `make check` | 本地开发 | 有完整 BSP/外部输入时执行严格依赖锁和 SCons dry-run；否则自动使用 source-only |
| `make test` | 快速迭代 | 只跑 Python 上位机测试和 host synth 测试 |
| `make release-check` | 发布前 | 在 `check` 之上检查 `VERSION`、`CHANGELOG.md` 和空白错误 |

完整构建仍由 `make build` / `make build-no-ui` 委托给 `tools/build.sh`，依赖变量和路径规则见 [编译与烧录](../projects/Edgi_Talk_M55_PocketJS/docs/编译与烧录.md)。

## 4. 变更分层

1. **协议/限制**：先改 `contracts/chart-contract.json`，再同步 Python 常量和 C 宏，最后更新文档和测试。
2. **板端行为**：改 `applications/pocketjs/`，用 `make test` 和 `make check` 验证；需要完整 BSP 时再 `make build`。
3. **界面行为**：改 `pocketjs-app/edgitalk-m55-smoke/`，用 `make build` 重新打 `.pocket`，不要手工改 `applications/pocketjs/generated/`。
4. **上位机行为**：改 `tools/edgitalk-companion/`，优先补 `test_edgitalk.py`；mock 测试不依赖板子。
5. **外部依赖升级**：确认 PocketJS/QuickJS 或 Rust 库确实有意升级，执行 `python3 projects/Edgi_Talk_M55_PocketJS/tools/check_dependencies.py --update`，并在变更说明中记录来源。

## 5. 发布路径

- `VERSION` 只包含一个语义化版本号。
- `CHANGELOG.md` 必须有对应版本的条目。
- 生成物不提交：`build/`、`Debug/`、`__pycache__/`、`.elf`、`.map`、`.sconsign.dblite` 等由 `.gitignore` 和 `make clean` 管理。
- 发布前执行 `make release-check`；完整固件构建和烧录只在具备 BSP、工具链和板子的环境执行。
