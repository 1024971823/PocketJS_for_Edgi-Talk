# 01 · 方案设计

> 项目：蔬菜大棚 AI 管家（一期：板载 AHT20 监测版）
> 硬件：RT-Thread × 英飞凌 Edgi Talk（PSoC™ Edge E84，出厂 RT-Thread + 小智固件）
> 日期：2026-10-26

## 1. 需求与范围

| 项 | 一期（本期） | 二期（规划） |
|---|---|---|
| 监测量 | 空气温度、湿度（板载 AHT20） | 土壤湿度(ADC)、光照(BH1750)、CO2(SCD4x/MH-Z19)、RS485 变送器 |
| 交互 | 语音问答实时值、报警状态；语音改阈值 | 定时巡检播报 |
| 控制 | 无 | 继电器（风机/水泵/补光灯）+ 阈值自动联动 |
| 报警 | 屏幕红字 + 红灯 + AI 可见可播报 | 服务端 notify 主动语音推送 |
| 服务端 | 官方 xiaozhi.me 云（免费） | 自建 xiaozhi-esp32-server（人设+RAGFlow 知识库） |
| 数据 | 不落库 | paho-mqtt 上报 + 历史曲线 |

一期刻意选"零接线"配置：板载 AHT20 直接可用，把整个链路（传感器 → 固件 → 协议 → 云端 LLM → 语音）先打通，二期再横向加传感器和纵向加控制。

## 2. 硬件与系统底座

- **主控**：Infineon PSoC™ Edge E84 —— Cortex-M55(400MHz, Helium+Ethos-U55 NPU) + M33 双核异构。小智应用跑在 M55 核上（RT-Thread 完整版），Secure/NS M33 负责启动链。
- **操作系统**：RT-Thread 标准版（官方 BSP `sdk-bsp-psoc_e84-edgi-talk` 自带，满足"使用 RT-Thread"的硬性要求——这块板子本身就是 RT-Thread 官方板卡）。
- **小智固件**：官方工程 `projects/Edgi_Talk_M55_XiaoZhi`，通过 WSS(443) 连接小智官方服务器 `api.tenclass.net`，与 xiaozhi-esp32 同协议（hello/tts/stt/llm/mcp/iot 消息、Opus 音频）。设备经 [xiaozhi.me](https://xiaozhi.me) 激活绑定。
- **传感器**：板载 AHT20（I2C）。不同批次/拓展板上 AHT20 所在总线不一（i2c1/i2c2/i2c0 均有可能），因此不依赖 `BSP_USING_AHT20` Kconfig 和 aht10 软件包，采用裸 I2C 驱动 + 上电自动探测（读法与官方 SDK `sensor_monitor.c` 实测代码一致）。

## 3. 软件架构

### 3.1 分层

```
┌─────────────────────────────────────────────────────────┐
│  小智官方云（api.tenclass.net / xiaozhi.me 控制台人设）    │
└───────────────▲─────────────────────────────────────────┘
                │ WSS：iot descriptors/states、mcp tools/list|call
┌───────────────┴─────────────────────────────────────────┐
│ 官方小智协议栈（xiaozhi.cpp / mcp_server / thing_manager）│  ← 不改动
├─────────────────────────────────────────────────────────┤
│ 本项目增量（applications/xiaozhi/greenhouse/，纯追加）    │
│  greenhouse_thing.cpp   IoT Thing「Greenhouse」          │
│  greenhouse_mcp.cpp     MCP 工具 self.greenhouse.*       │
│  greenhouse_sensor.cpp  采样线程 + 报警状态机 + UI/LED    │
├─────────────────────────────────────────────────────────┤
│ RT-Thread 设备框架（I2C/PIN/MUTEX/线程）│                  
└─────────────────────────────────────────────────────────┘
```

### 3.2 数据流

1. `gh_sens` 线程每 10s 读 AHT20 → 合理性过滤（-40~85℃ / 0~100%RH）→ 写缓存（互斥锁）。
2. 阈值判断（默认温度 5~35℃、湿度 30~90%RH），**连续 3 次**越界才置位报警（去抖），恢复同理。
3. 报警变化沿：红灯 P16_7 亮/灭；每次采样推送屏幕标签（报警文本 "⚠" 前缀 → 补丁中显示红色）。
4. AI 感知双通道：
   - **IoT Thing**：`temperature/humidity/alarm/alarm_description` 四属性。WebSocket 连接及每次 `iot_invoke` 后，官方 `send_iot_states()` 上报全部 states → 服务端注入 LLM 上下文。特点：AI"被动知道"，但值的新鲜度取决于上次 states 上报。
   - **MCP 工具**：`get_report / get_temperature / get_humidity / get_alarm_status / set_thresholds`。LLM 在对话中 `tools/call` **实时取值**，是新协议（小智 v2.x）的主路径。
   - 两者并存 = 无论服务端走哪种机制都能答。
5. 语音改阈值 → LLM 调 `SetThresholds`（Thing 方法）或 `self.greenhouse.set_thresholds`（MCP）→ `greenhouse_set_thresholds()` 规整入参（上下限不颠倒、限幅）→ 重置去抖计数，立即生效。

### 3.3 关键设计决策

| 决策 | 理由 |
|---|---|
| overlay 增量而非改官方工程 | 小智协议栈/WiFi/音频/LVGL 复用官方实现；BSP 升级不冲突；集成仅 2 步 |
| AHT20 裸 I2C 自动探测（不用 Kconfig/软件包） | 真板上 AHT20 所在总线未定（RECON.md 实测线索：可能在拓展板），探测 i2c1/i2c2/i2c0 免去 menuconfig 依赖，集成更少一步、适应性更强 |
| Thing + MCP 双注册 | 兼容新旧服务端行为，问答体验最稳（详见 3.2） |
| 报警本地化（屏+灯），不主动触发对话 | 官方云 `notify` 是服务端→设备单向；固件无法主动发起对话。用户问"有什么报警"时 AI 立即播报（alarm 属性/工具在）。主动语音推送列入自建服务端阶段 |
| 数值用 0.1 精度整数（253=25.3℃） | Thing/MCP 数值类型仅 int；描述中已向 LLM 说明换算；`get_report` 返回人类可读字符串 |
| 阈值存内存，掉电复位 | 一期求简；二期用 easyflash/fal 持久化 |
| `INIT_APP_EXPORT` 自注册 | 官方 `iot_initialize()` 硬编码注册 3 个 Thing，改它属于侵入；本模块自注册向单例追加，顺序无关 |

### 3.4 线程与同步

| 线程 | 职责 | 栈/优先级 |
|---|---|---|
| `gh_sens`（本项目） | 采样+去抖+UI/LED | 2048 / 25 |
| `xz_ui`（官方） | LVGL 渲染，经消息队列收指令 | 10K / 25 |
| 小智主线程（官方） | WSS 收发，iot states 上报、MCP tools/call 回调 | 官方设定 |

共享状态只有传感器缓存/阈值/报警文本，统一 `gh_lock` 互斥锁保护；UI 推送走官方消息队列（天然线程安全）。

## 4. 二期扩展路线

1. **外接传感器**（40-pin 排针）：土壤湿度 → ADC 直读（官方 `adc/adc.c` 有示例）；光照 BH1750、CO2 SCD4x → I2C 挂 i2c1/i2c2（RT-Thread 软件包 `bh1750`、`scd4x`）；工业 RS485 多合一 → `rs485` + `agile_modbus` 软件包。扩展方式与本期完全一致：新文件 + Thing/MCP 注册。
2. **控制**：继电器Thing/ MCP 工具（`self.greenhouse.fan_on` 等），再加本地自动联动（温度>上限且持续 N 分钟 → 开风机）。
3. **自建服务端**：xiaozhi-esp32-server（Docker，2核2G 起），收益：专属人设与 RAGFlow 种植知识库、历史数据入库与曲线、`notify` 主动语音播报报警（服务端定时查设备 states 主动下发）。固件侧只需把配网页"高级选项"里的 OTA 地址指向自建端。
