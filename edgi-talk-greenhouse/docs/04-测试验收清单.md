# 04 · 测试验收清单

> 按顺序勾选。串口 = KitProg3 虚拟串口 115200-8N1。
> 语音唤醒词以固件实际为准（官方 Edge Impulse 模型默认"小睿，小睿"）。

## A. 固件基础

- [ ] A1 编译通过：Studio 构建 `Edgi_Talk_M55_XiaoZhi`，输出 `xiaozhi_greenhouse` 组参与编译
- [ ] A2 串口启动日志出现：
      `greenhouse sensor started (AHT20 auto-probe i2c1/i2c2/i2c0, period 10000 ms)`，随后出现 `AHT20 found on bus i2cX`（约 3 秒后）
- [ ] A3 `msh /> greenhouse_status` 打印温湿度，`sensor found : yes` 且 `data valid : yes`
- [ ] A4 屏幕头部下方出现温湿度标签："大棚 温度25.3℃ 湿度60.5% 正常"（10 秒内刷新）

## B. 联网与 AI 感知

- [ ] B1 设备连接小智服务器（屏幕 Standby / 串口 WSS 连接日志）
- [ ] B2 串口能看到 iot descriptors/states 里含 `"Greenhouse"`（AI 已感知设备）
- [ ] B3 串口能看到 mcp `tools/list` 返回中含 `self.greenhouse.get_report` 等 5 个工具

## C. 语音问答（每题 AI 都必须报出与 A3 一致的数量级，禁止编造）

| # | 说法 | 预期 |
|---|---|---|
| C1 | "现在大棚温度多少？" | 报出实时温度，误差 ±0.5℃ |
| C2 | "湿度正常吗？" | 报湿度 + 正常与否 |
| C3 | "大棚有什么报警吗？" | "正常"或具体报警原因 |
| C4 | "大棚现在整体情况怎么样？" | 温湿度 + 状态小结（应调 get_report） |

## D. 阈值语音修改

- [ ] D1 说"把温度报警上限改成 32 度"→ 串口出现 `thresholds updated: T[5,32]...`，
      `greenhouse_status` 中 `thresholds` 一行同步变化
- [ ] D2 说"查一下现在的报警阈值" → AI 能读出（由 get_thresholds 语义通过人设/属性回答；
      若答不出，记录为已知限制，不影响验收）
- [ ] D3 重启板子，阈值回到默认 T[5,35] H[30,90]（掉电不保存属预期）

## E. 报警链路（人为触发）

1. **触发方法**（任选其一）：
   - 哈气/捂热：手指捏住板上 AHT20（位于 40-pin 排针附近的小芯片，丝印 AHT20），
     或对板哈气提高湿度
   - 降阈值更快：说"把湿度上限改成 20"（当前湿度高于 20 即越界）
2. 验收点：

- [ ] E1 越界后屏幕标签变红并显示 "⚠ ..." 报警文本（约 30 秒内 = 3 次采样去抖）
- [ ] E2 红灯（P16_7）亮起
- [ ] E3 `greenhouse_status` 显示 `alarm : ALARM` 与报警文本
- [ ] E4 询问"有什么报警吗" → AI 播报具体原因（如"湿度过高"）
- [ ] E5 恢复正常（拿开手/改回阈值）后约 30 秒：红灯灭、屏幕恢复白色正常文本、AI 答正常

## F. 稳定性（挂机）

- [ ] F1 连续运行 ≥ 2 小时：串口无 hardfault/内存错误，温湿度持续刷新
- [ ] F2 断网 1 分钟再恢复：小智自动重连，语音问答恢复（传感器链路本就离线可用）
- [ ] F3 反复触发/解除报警 5 次：无重复报警、无误报残留

## G. 已知限制（不算失败项）

- 报警不会让小智"主动开口喊话"（官方云 notify 为服务端单向能力）；用户询问时才播报。
- 温湿度为 0.1 精度整数上报，AI 口播"25 度 3"属正常。
- 语音控制红灯（官方 Led Thing）与报警红灯共用引脚，报警状态会在下一次采样覆盖语音设置。
- 阈值掉电不保存（二期 easyflash）。

## H. 问题反馈模板

4. `greenhouse_status` 输出
5. 复现步骤
